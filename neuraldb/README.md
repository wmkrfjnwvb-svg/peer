# neuraldb：全部由模型计算的数据库 demo

模型自己读表里的每一行，自己做所有和数据有关的判断，我们只从它的输出里拿**指针**或**计算结果**。不使用外部算子。

## 模型做什么

| 层级 | 模型输出 | 说明 |
|---|---|---|
| 每一行 | **是否选中**（选中分数） | 这一行是否满足 WHERE 条件 |
| 每一行 | **读出的值**（每一位数字一个分类） | 目标列的值，排序、求和用 |
| 每个查询 | 结果类型、排序方式（行号 / 升序 / 降序）、第几页 | |

结果直接从这些输出得到：

| 查询 | 结果 |
|---|---|
| `SELECT * … PAGE k` | **指针**：选中的行按读出的值排序，取第 k 页，加上"是否还有下一页" |
| `MIN` / `MAX` | **指针**：排序后的第一个选中行 |
| `COUNT` | 选中的行数 |
| `SUM` / `AVG` | 选中行读出的值相加（AVG 再除以行数，保留两位小数，向下取整） |

每一行由模型独立读取，所以在小表上训练的模型可以直接用在大表上。能不能在大表上保持精确，取决于**每行的判断错误率**，评测会单独报告这个数字。

## 模型结构（`model.py`）

```
SQL 查询 ──→ 查询编码器（Transformer）──→ 查询向量
                                         │ 交叉注意力
表的每一行：[行标记, 列1的6位数字, 列2的6位数字, …]
       └──→ 行读取器（每行内部自注意力 + 对查询的交叉注意力）──→ 行状态
                                                              ├─ 选中头
                                                              └─ 读值头（6 位 × 10 类）
```

- 数字按位输入，每一位带位置编码（个位、十位……），模型自己学会比较大小。
- 文字类的值作为词输入。
- 大表推理时按块读取（行之间互不依赖，结果和一次读完完全一样）。

## loss 设计（`losses.py`）

要得到完全正确的结果，需要**每一行都判断正确**，所以 loss 针对最难的行，而不是平均水平：

| 部分 | 设计 | 解决什么问题 |
|---|---|---|
| 选中：边界加权 | 值紧贴条件边界的行（`年龄 > 30` 时年龄是 30、31 的行）权重 ×5 | 错误主要出在边界行 |
| 选中：间隔 | 判断的分数必须超出 ±5（概率约 0.99），没超出就继续受罚 | 不允许"勉强判对" |
| 选中：困难行挖掘 | 每个 batch 中损失最大的 2% 的行再算一遍 | 罕见的错误模式持续得到训练 |
| 选中：正负样本平衡 | 选中的行少时，对选中的行加权 | |
| 读值：加性间隔 | 每一位数字的交叉熵，正确类别的分数先减 1 再算 | 正确数字和第二名之间留出距离 |
| 读值：选中行加权 | 选中行的读值损失 ×3 | 选中行的值构成答案 |
| 全局一致性 | 用"软"判断算出的 COUNT / SUM 必须等于真实值 | 抓住逐行损失被平均掉的系统性偏差 |
| 查询级 | 结果类型、排序方式、页码的交叉熵 | |

另外，训练时**表的行数逐步增大**（从 4 行到 1000 行），并且条件里的常量大多取自表中已有的值，保证每张表都有边界行。

## 训练数据

每个 batch 都随机生成全新的表（2–6 列，整数列或文字列）和查询，模型不可能背下数据。标准答案在 `tests/test_neuraldb.py` 中和 SQLite 对拍。

## 运行

```bash
# 4 × RTX 4090
torchrun --nproc_per_node 4 -m neuraldb.train --out runs/neuraldb \
    --d 512 --r-layers 6 --batch 16 --n-max 1000 --steps 200000

# 按表的行数评测：完全正确率、每行错误率、置信度阈值下的回答率和准确率
python -m neuraldb.evaluate --ckpt runs/neuraldb/last.pt --sizes 10,100,1000,10000,100000
```
